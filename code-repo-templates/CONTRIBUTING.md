# 代码贡献约定（待采用）

本文件是供复制和整合的模板，当前没有修改真实代码仓库。

1. 从最新 `master` 建功能分支，一次完成一个可观察结果；不直接改主干。
2. 任务卡先写输入、正常输出、失败/取消/DS STOP、机械/电控前提和验收条件。
3. 小步提交并构建，相关自动检查通过；控制改动必须实车验证并记录完整代码 SHA、参数和逐次结果。
4. 知识库文档提交后，在代码 PR 引用它的具体 commit。知识库记录被测代码 SHA，两个仓库可互相追溯。
5. 普通变更至少 1 名非作者批准；驱动、取球/送球/发射、自动、停止、硬件参数和共享接口等核心控制至少 2 名非作者，其中至少 1 名了解并核对实车。
6. 更新主干、解决冲突或批准后修改时，重跑构建与受影响测试、更新证据并重新审批。
7. 整合负责人合并后，对最终 `master` SHA 构建和冒烟；整车验收通过才可标记比赛版本。
8. 能接着做的同学独立复现并完成短交接；不要只在一人的电脑上保留参数或未提交代码。

代码构建、功能合并和整场可用是三个不同阶段。关键用例失败或证据缺失时不合并；已合并的回归通过修复/回退 PR 处理，不强推抹历史。

采用时补充：团队知识库地址、任务卡路径、实际构建/测试入口、整合负责人。不要预填不存在的 CI 检查名称或账号。
