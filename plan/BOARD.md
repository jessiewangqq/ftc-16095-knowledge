## 先确定本场要做什么

- 自动主目标：本车在 30 秒内争取 **2 次有效 TIP**；先验证第一次，时间有余量再挑战第三次。离墙是途中动作，独立短离墙程序仅作移动练习和失败备用。
- 手动主线：驾驶 → 取球 → 停车瞄准 → 发射 → 翻转时停球 → 确认目标和残留 → 再取球，结束前回装载区。
- 共同前提：大家拿得到同一份程序；能停止；控球数量与颜色合规；参数、配置和测试记录能对应。
- P10 花塔与 P11 花园先演示现有机构再决定是否选入。选入时同时安排人和用车时间，不能只往清单里加目标。

## 怎样更新

现场核对后，按实际情况选：**待认领 / 进行中 / 待实车 / 待检查 / 已通过动作测试 / 已合并 / 已整场验收 / 阻塞 / 撤出本场**。只读文档任务可以注明“不涉及代码合并”。不要为走完一条箭头而补写没有发生的步骤。

1. 每次只更新发生变化的行，写日期、下一步和对应测试记录；曾经失败的记录保留。
2. “已通过动作测试”要有代码完整 SHA、参数和真实结果；“已合并”要有代码 PR；“已整场验收”要有最终版本的整场记录。三者不能互换。
3. 子任务较多时，用[任务模板](../tasks/TEMPLATE.md)另建小卡，并在本页增加行。一张小卡应能在一次训练里看到结果，进展仍只放本页。
4. 普通代码改动由至少 1 位非作者 review；核心控制由 2 位非作者 review，其中 1 位熟悉实车，详见[合并门槛](../tests/MERGE-GATE.md)。
