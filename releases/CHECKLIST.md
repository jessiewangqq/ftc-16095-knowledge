# 比赛版本检查与恢复

先挑一个确定版本作为候选，按下面的清单检查，再决定是否用于比赛。标签名由队伍维护者确定，不能把还没测过的版本标成可用。

## 整车检查

- [ ] 已完成[功能合并检查](../tests/MERGE-GATE.md)，最终主干代码可以构建。
- [ ] 代码和参数已提交，实际安装包、完整 SHA、配置和硬件对应这台车。
- [ ] 红蓝双方、主用和备用入口、初始化、取消、DS STOP、残留球恢复都检查过。
- [ ] 机器人重启后参数仍正确，比赛需要的功能不用临时依赖调参电脑才能运行。
- [ ] 按规则的比赛时间演练：30 秒自动、8 秒转场、120 秒手动，记录有效 TIP、结束状态和故障处理。
- [ ] 建议红蓝各连续 3 场，逐场记录。没有真实对手时说明模拟范围，不能写成已经完成对抗。
- [ ] 程序、机械、电控和操作同学一起确认。选入比赛的动作没有未解决的停止、控球或规则关键失败；若撤出失败动作，备用方案也已经重新验收。

时间规则以[规则入口](../rules/README.md)为准。重复场数是队内建议，实际赛程与本地通知另行确认。

## 确定比赛版本

把代码 SHA、参数、安装包、实测记录和检查人填入[版本登记](REGISTRY.md)。请另一位同学照着[交接记录](../handoff/TEMPLATE.md)取代码、安装并操作。

版本确定后若继续改代码或参数，说明影响范围、重新测试和 review，再更新登记。不要悄悄改变内容却继续沿用旧的测试结论。

## 如果新版本出了问题

1. 记下当前程序、参数和故障现象，暂停继续使用故障版本。
2. 找到之前验证过的版本，确认它仍适合现在的机械和端口配置。
3. 停止机器人运行后，按约定重新安装旧包和对应参数。
4. 若仓库也需要撤销代码，通过 revert PR 留下记录，不强推主干抹掉历史。
5. 再检查启动、停止和相关动作，必要时重跑整场，登记真正装上的版本。

Git 中恢复了代码，不会自动把机器人上的程序换回来。
