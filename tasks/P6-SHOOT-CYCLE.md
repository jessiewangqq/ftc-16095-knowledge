# P6 送球、停球与完整射击循环

谁做 / 谁能接着做：待认领，认领后将名字填到[唯一任务看板](../plan/BOARD.md)。本卡不另存任务进展。

## 为什么做

把 P2—P5 组合成能结束、能恢复的得分动作，再给自动复用。开始条件、取消条件与机构输出要提前约定。

## 当前已知

公开版会判断瞄准、速度和角度就绪，并有松 RT、RB、无有效距离等取消处理。但连续送球后，ready 变差不会仅因此自动撤销送球。主手动没有持续判断朝上 CELL 的放行条件；这需要实车与操作约定，不能仅凭缺少某变量断言已违规。

## 接下来做什么

1. 按 RT → 瞄准/速度/角度满足 → 开挡板和送球 → 松 RT 取消。明确 RT 不是“精确发一颗”的按钮。
2. 给四种阶段分别写处理表：尚未准备好、挡板刚开、反向阶段、正在供球。每种都覆盖 RT 释放、RB、B、DS STOP、距离无效、转速下降、明显偏转和蜂巢翻转。
3. 每格写电机输出、挡板目标、下一阶段与恢复条件。决定哪些异常由软件取消、哪些由操作手及时松 RT，不因每次转速抖动反复开关门。
4. 分别测松 RT 时 LT 没按/仍按。取消射击送球不等于禁止默认取球或预热。实测取消到最后一球离开的延迟。
5. 完整跑取球 → 停车瞄准 → 发射 → 翻转停球 → 确认朝上目标与残留 → 再取球，残留交给 P3 核对。

## 怎样算通过

- 所有选定取消/异常用例符合预先处理表，关键项无未解决失败。
- 红蓝各连续 5 轮，共 10 轮；记录真实 TIP、命中、球量与每轮耗时，不只演示飞轮空转。
- 翻转后不继续追射向下 CELL；重新确认合法目标后再开始。HIGH 是程序命名，不是规则要求必须有的接口。
- 另一位同学可复现，操作说明包含取消和恢复。按核心控制 2 位非作者 review，其中 1 位熟悉实车。
