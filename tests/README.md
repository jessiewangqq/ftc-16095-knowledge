# 测试记录

测试的目的，是说明某一版程序在什么条件下做到了什么。不能只写“调好了”，也不能只放一段没有版本信息的视频。

- 第一次写记录：复制[测试模板](TEMPLATE.md)，文件名用 `YYYY-MM-DD-任务ID-简短说明.md`。
- 看一份填写要求：[RB 卡球处理示例](RB-UNJAM-EXAMPLE.md)。这是待执行的教学模板，不是这台车的成绩。
- 判断能否合并：[合并要求](MERGE-GATE.md)。
- 准备比赛版本：[整车检查](../releases/CHECKLIST.md)。

## 一次正式测试要留下什么

写清代码完整 SHA、硬件和参数、起始状态、操作步骤、预期、每次实际结果以及视频或日志时间点。代码和参数有未提交修改时，先保存并提交，再构建安装；不能用一个旧 SHA 代表后来改过的内容。

重复次数在测试前约好。5 次或 3 场等数字是队内建议，具体见任务卡，不是官方规定。失败要保留，修好后追加新版本的测试结果，不覆盖旧结果。

视频存放在团队授权的位置，记录中只链接需要的片段。上传前确认访问权限，避免队友点开后看不到。
