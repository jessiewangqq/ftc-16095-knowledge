# 动作限制：写程序与练车时要对照什么

核对：2026-11-03。场上规则来自[第 11 章 TU07](https://ftc-resources.firstinspires.org/ftc/archive/2027/game/manual-11)，机器人限制来自[第 12 章 TU05](https://ftc-resources.firstinspires.org/ftc/archive/2027/game/manual-12)，CONTROL 定义来自[第 16 章 V1](https://ftc-resources.firstinspires.org/ftc/archive/2027/game/manual-16)。

下表左列是规则摘要，右列是本队可以采用的检查办法；检查办法不是官方要求必须使用的技术方案。

| 场景与条款 | 规则要求 | 程序与练车怎样检查 |
|---|---|---|
| 开场 G304 | 合法起始姿态：完全在本方半场、接触围墙、不在 LOADING ZONE，不接触 FLOWER 或进入其计分体积；接触 4 个指定预装 POLLEN，INIT 后完全静止 | 把实车、球和场地一起摆出来检查，不能只看路线图 |
| AUTO G401 | 驾驶员不能在自动阶段提供操控输入，规则列出的开始、停止及安全例外另论 | 一次启动完成任务；不能临时用手柄修正路径 |
| AUTO 对抗 G402 | 不得干扰对方联盟的自动阶段 | 规划路线时避开对方半场作业；进入对方半场可能造成违规，不能把干扰当成自动任务 |
| 转换 G403、终场 G404 | 转换期不能有电力驱动的运动；阶段结束要停止，不能故意继续完成动作 | 连着测 AUTO → 转换 → TELEOP → 终场；特别检查 INIT、待机电机和已开始的投球动作 |
| 控球 G407 | 同时 CONTROL 的所有得分物总数不能超过 4 | 预装、取球、发射、卡球处理后都观察实物；不能只相信屏幕计数 |
| 球色 G408 | 不能 CONTROL 对方 NECTAR | 检查混合颜色情况下的取球路线和操作；自动识色只是可选方案 |
| HIVE 落球 G409 | 新从翻转 HIVE 落下的球，在接触机器人以外的其他物体前，不能由该机器人接住或偏转 | 不把“停在下面直接接球”设计成得分循环；正常地面取球另论 |
| NECTAR 入塔 G410 | 只有最后 60 秒，NECTAR 才能进入 FLOWER 计分体积 | 操作手看场地计时器；若写软件提醒或限制，要测计时起点是否正确 |
| 裁判要求停用 G413 | 按 Driver Station 的停止键，并放下手柄 | 队员都要知道 DS 停止键在哪；普通功能取消键不能替代这一流程 |
| HIVE 互动 G417 | 只通过向朝上的 CELL 发射球影响 HIVE，不能推、拉或阻挡它 | 翻转后重新确认朝上目标；程序知道的状态要与真实装置对得上 |
| FLOWER 互动 G418 | 球只能从顶部进入；只能从底部取出 POLLEN | 不设计侧面塞球、侧面取球或从底部抽出 NECTAR 的动作 |
| 对抗 G419–G421 | 不得违规损坏、缠住或掀翻对手；PIN 不得超过 3 秒 | 驾驶员练会主动让开；不得把持续顶住当成常规战术 |
| 人员投球 G425–G427 | 遵守 NECTAR 解锁和投放方式；不能直接接触机器人或把球递进车里 | 投球同学与操作手一起练，先落本方装载区地垫，再让车取球 |

## “控制了几个球”看什么

CONTROL 不仅包括仓内的球。球被机器人托住、卡在车上或车下，以及机器人有意把球推向指定位置或方向，都可能属于 CONTROL。路过时偶然碰到球、已离开机器人的发射球等，不能一概当成控制。判定看官方定义与真实过程。

课堂里“仓内还有 2 个球，但屏幕显示 0”的例子是**假设场景**，不是已确认的实车故障。它提醒我们：软件清零不会让真实球消失。卡球处理时反转退球，松开后还应核对剩余球数；不能为了继续吸球而把实物数量当作 0。具体实现与实测写进[卡球处理任务](../tasks/P2-RB-UNJAM.md)和[测试记录](../tests/RB-UNJAM-EXAMPLE.md)。

G407、G408 的处罚会区分情况，正文也有短暂失误等例子；这些例子不是让我们设计成“先多吸再排掉”。反复超过 4 个，或反复吸入对方 NECTAR 后再排出，仍可能被认为是有策略的违规。

## PIN：顶住别人，退一点就重新计时吗

PIN 指通过直接接触，或把对方压在场地结构等间接接触方式，阻止对方机器人移动。G421 不允许超过 3 秒。

计数结束需要满足以下任一条件：

- 两车间距至少 2 ft（约 61 cm），并保持超过 3 秒；
- 任一机器人离开 PIN 开始位置至少 2 ft，并保持超过 3 秒；
- 原本 PIN 对方的机器人自己被 PIN。

前两项刚达到距离时计数暂停；未保持够时间又回来，可能继续原计数。因此不能“退一点马上再顶”，就当作获得新的 3 秒。超过限制时，每次为 MAJOR FOUL，未纠正时每再过 3 秒再加一次 MAJOR FOUL。依据：[G421](https://ftc-resources.firstinspires.org/ftc/archive/2027/game/manual-11)。

## 比赛配置与尺寸也会影响程序

- **R704：** 比赛中编程电脑等非 DS 设备必须断开机器人 Wi-Fi。控制、调试与遥测数据流使用 FTC Driver Station App；额外日志 / 数据流服务（如 FTC Dashboard、FTControl Panels）及连续视频流受禁。关网页不等于服务停止；项目有依赖也不等于比赛时一定启动了服务，要核对实际配置并重启检查。
- **R102、R103、R105：** 起始机器人须自支撑并处于 18 × 18 × 18 in 的范围内；展开后不得超出 18 × 24 × 29 in，29 in 是竖直高度，且展开限制必须由物理结构保证，不能只靠软件限位。预装球可按 R102 超出起始尺寸约束，不可把这项例外套到机器人本体。
- **G403 与 INIT：** 赛前初始化可以帮助机器人保持合法起始姿态；但 AUTO 与 TELEOP 之间的禁动要求仍然存在。若 TELEOP 的 INIT 会带动电机或舵机，不能随意在转换期运行它。

修改程序能否合并，按[本队合并要求](../tests/MERGE-GATE.md)检查；比赛规则符合性和队内测试通过，两件事都要确认。
