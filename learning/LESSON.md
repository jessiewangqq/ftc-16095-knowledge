# Git 协作与 FTC 知识库：60 分钟课程

接着上次“用 AI 做一个 FTC 功能”，这次练习把功能交给队友：代码能找到、动作能说明、测试有记录，换个人也能继续做。

## 五个章节

| 章节 | 这段要弄清什么 | 对应资料 |
|---|---|---|
| 01 用 Git 一起改程序 | 怎样认清版本？各开分支后怎样共享改动？ | [Git 入门](GIT-QUICKSTART.md) |
| 02 把一个功能测清楚 | 比赛需要它做什么？上车要测什么、怎样记？ | [RB 任务](../tasks/P2-RB-UNJAM.md)、[测试示例](../tests/RB-UNJAM-EXAMPLE.md) |
| 03 检查后再合并 | 请谁检查？遇到冲突或试车问题怎么处理？ | [合并要求](../tests/MERGE-GATE.md)、[恢复方法](../releases/CHECKLIST.md) |
| 04 一起建知识库 | 规则和结果放哪里？怎样一起更新并交给 AI 使用？ | [知识库入口](../README.md)、[AI 使用方法](AI-WORKFLOW.md) |
| 05 两个人试一遍 | 怎样合作改好、检查、合并一张测试卡？ | [15 分钟练习](PAIR-EXERCISE.md) |

## 课堂时间

- 0–5 分钟：回顾上次功能，讨论“队友明天接着做，还缺什么”。
- 5–17 分钟：版本、仓库、提交、同步和分支。
- 17–27 分钟：用 RB 卡球处理的例子讲任务、实车测试和记录。
- 27–32 分钟：判断 PR 能否合并，讲检查、冲突和恢复。
- 32–45 分钟：知识库的目录、每日记录和 AI 使用。
- 45–60 分钟：两人修改测试卡、提意见、修改和合并。

课前准备账号、成员权限、练习分支或练习仓库、示范 PR 和纸质卡。规则内容以[规则入口](../rules/README.md)的版本说明为准，机器人进度以实际记录为准。

课堂结束后选一项真实任务，约好谁来做、谁一起测、什么时候再看结果。
